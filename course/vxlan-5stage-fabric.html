VXLAN 5-Stage Fabric

The same lab, shaped like Kentik's demo DFW1 site. Servers plug into top-of-rack switches, which are the VTEPs. Leaves and spines form two pods, superspines tie the pods together, and edge routers bring the internet in. Every switch sends sFlow and answers SNMP with LLDP, so Kentik draws this exact map.

The VXLAN story is the same at any size: the ToR samples the original packet, and every switch above it only sees VTEP-to-VTEP UDP 4789 unless the collector decodes VXLAN. A 5-stage fabric just has more of those blind hops.

Run it and onboard it

Two commands pick the topology

export VXLANLAB_TOPOLOGY=5stage      # or --topology 5stage on any command
sudo -E python3 -m vxlanlab aliases --apply
sudo -E python3 -m vxlanlab run --snmp

# Kentik: 22 devices, a site with five layers
export KENTIK_EMAIL=… KENTIK_API_TOKEN=… KENTIK_PLAN_ID=…
export KENTIK_AGENT_ID=… KENTIK_SNMP_CREDENTIAL=lab-snmp
python3 -m vxlanlab -t 5stage kentik onboard \
    --site-name "VXLAN Lab DFW1"

Use its own site name. Both labs can live in one Kentik account at once: names and sending IPs don't overlap. Leave VXLANLAB_TOPOLOGY unset and everything runs the 3-tier lab as before.
